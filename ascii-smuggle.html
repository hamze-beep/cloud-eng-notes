Kubernetes Pod Security Standards

Pod Security Standards define three policy levels: Privileged, Baseline, and Restricted. Each level builds on the previous, adding additional restrictions.

Baseline Policy

Prevents known privilege escalations. Targets ease of adoption for common containerized workloads. Key restrictions:

  • HostProcess: false
  • Host Namespaces: hostNetwork, hostPID, hostIPC must be false

Restricted Policy

Heavily restricted, following current Pod hardening best practices. May impact compatibility. Key restrictions beyond Baseline:

  • Volume Types: only configMap, csi, downwardAPI, emptyDir, ephemeral, persistentVolumeClaim, projected, secret
  • Privilege Escalation: allowPrivilegeEscalation must be false
  • Running as Non-Root: must run as non-root user
  • Seccomp: must use RuntimeDefault or Localhost profile

Implementation

Apply via namespace labels: pod-security.kubernetes.io/enforce: restricted
